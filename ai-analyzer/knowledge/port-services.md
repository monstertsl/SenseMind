# 端口与服务语义对照（溯源分析必读）

进行溯源分析时，必须结合**目的端口**判断目标服务类型，进而判断「攻击类型与目标服务是否匹配」。攻击类型与目标服务不匹配时，通常是误报或无效攻击。

## 核心原则：以实际请求判断服务，端口只是参考

**端口表是辅助参考，不是判定依据。真实服务类型必须以实际请求为准**——即结合协议解析结果（HTTP method/URL、TLS SNI、payload 结构）、应用层协议字段综合判断。

原因：
- 实际部署中服务可能监听任意端口（非标配置、容器端口映射、中间件端口迁移、运维自定义等）
- 同一端口可能承载多种服务（如 8080 可能是 Tomcat、Nginx、Python Web，甚至是管理后台）
- 攻击特征是否有效，取决于**目标服务的真实类型**，而非端口默认映射

**正确做法**：先用实际请求的协议特征判断目标服务，再用端口做交叉验证；当两者冲突时，以实际请求为准，并在结论中说明差异。

## 溯源时的服务判断流程

判断目标服务类型应**优先依据实际请求特征**，端口仅作交叉参考：

1. **协议解析结果**：Suricata/Zeek 是否将流量识别为 HTTP / DNS / TLS / SMB 等。若 app_proto 已识别，以识别结果为准。
2. **payload 结构**：
   - 含 HTTP 请求行（`GET /xxx HTTP/1.1`）、HTTP 响应头（`HTTP/1.1 200`）→ Web 服务
   - 含 SMB 协议字段、NTLMSSP → SMB
   - 含 DNS query/response → DNS
   - 含 TLS ClientHello/证书 → TLS
3. **应用层字段**：HTTP method/URL/host、TLS SNI、DNS query name 等直接反映服务类型。
4. **端口交叉验证**：用端口表验证上述判断是否一致。若不一致，以协议/payload 实际识别为准，并在结论中说明端口与服务的差异。

## 端口与攻击类型匹配性判断要点

1. **端口与攻击类型的匹配性是「参考信号」，不是「判定铁律」**：
   - 端口与服务一般存在对应关系，但实际部署中服务可能监听任意端口，需结合协议元数据综合判断真实服务。
   - 当目的端口与攻击类型的常见服务明显不一致时，应提高警觉、重点检查 payload 结构和时间戳，而不是直接判定为误报——可能是非标部署，也可能确实是误报。

2. **重点检查 payload 真实性质**：端口不匹配时，结合 payload 内容综合判断流量在传递什么，可能是攻击、也可能是其它类型的通信，需逐一排查，不要只盯着攻击特征字符串下结论。

3. **扫描探测行为识别**：同一源 IP 在短时间内对多个端口发起访问，倾向端口扫描/侦察行为，而非单一漏洞利用。

4. **不要因"端口不匹配"就强制判定为误报**：需结合 payload 内容、协议解析结果综合判断，给出有依据的结论。

## payload 内容判断（溯源关键）

payload 承载的可能是多种内容，应客观判断其形态，而非机械分类：

1. **直接的请求/响应交互**：payload 是通信双方直接交换的数据（如 HTTP 请求/响应），攻击特征若出现在这里，是实时的。
2. **某种数据的传输内容**：payload 本身是被传输的数据（如文件内容、日志记录、配置、文档等），此时其中出现的攻击特征字符串，可能只是被传输数据里携带的内容，而非实时攻击。
3. **编码/二进制数据**：Base64、十六进制、序列化等，需先解码再判断内容。

判断思路：先看 payload 整体在表达什么（是交互还是数据搬运），再看其中的攻击特征字符串处于什么语境，最后结合时间等其它信息综合判断。

## 时间信息判断（溯源关键）

1. 关注 payload 内容中出现的任何时间信息（时间戳、日期、日志时间等）与告警时间的关系。
2. 若 payload 中出现的时间信息明显早于告警时间，说明这些内容可能是历史数据，而非当前实时发生的行为。
3. 结合 payload 形态与时间信息综合判断，避免把历史记录中的攻击特征误判为当前攻击。

## 流量四元组（源IP:源端口 → 目的IP:目的端口）判断要点

1. **源端口**：攻击者源端口通常是随机高位端口（>1024）；固定低位端口可能是服务端。
2. **目的端口**：见上表，判断目标服务类型。
3. **协议**：`tcp`/`udp` 是传输层；还需结合应用层协议（HTTP/SMB/DNS/TLS）判断真实服务。
4. 四元组 + 端口语义 + payload 结构 + 时间戳，四个维度结合，才能准确溯源，避免只看源/目的 IP 就下结论。
